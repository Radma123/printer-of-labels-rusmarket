## Overview

### Что этот код делает

Один файл на 743 строки, без сборки, без npm, без фреймворка. Отвечает за:

* поиск детали и автодополнение по каталожному номеру;
* перевод наименования на пять языков с возможностью правки вручную;
* **превью этикетки, которое можно вращать, масштабировать и редактировать мышью**;
* печать, сохранение PNG/TSPL, запоминание настроек в `localStorage`.

Центральная механика — редактор макета: пользователь тянет блок мышью,
блок едет, картинка обновляется, и напечатается ровно то, что видно.

### Почему выбран такой подход

**Почему без фреймворка.** Приложение раздаётся `server.py` как статические файлы.
Ни сборки, ни зависимостей, ни `node_modules`. Правка интерфейса — это правка
одного файла и `Cmd+R` в браузере. React дал бы декларативные компоненты,
но потребовал бы либо сборки, либо CDN, либо ручного `createElement` без JSX.
На один экран с постоянным набором элементов выигрыш не окупает цену.

**Почему превью — картинка с сервера, а не вёрстка.** Это главное архитектурное
решение всего проекта, и оно объяснено в шапке файла (строки 1–10):

> Превью — не отдельная вёрстка этикетки, а та самая картинка 203 dpi,
> которую рисует `render.py` и которая уходит на принтер.

Наивная альтернатива — сверстать этикетку на HTML/CSS в тех же миллиметрах.
Тогда браузер рисует одно, Pillow другое, и они расходятся на метриках шрифтов,
округлениях, letter-spacing. Здесь браузер **не рисует этикетку вообще**:
он показывает `<img src="data:image/png;base64,...">` и накрывает её прозрачными
`<div>`-рамками, за которые можно тянуть.

Цена: каждое движение мыши требует нового PNG с сервера. Смягчено дебаунсом
(110 мс при перетаскивании, 300 мс в остальных случаях) и понижением качества
на время драга (`scale=2` вместо 4).

**Почему поворот — CSS.** Пользователю удобно смотреть на этикетку в портретной
ориентации, а печатается она повёрнутой. `transform: rotate()` кратный 90°
не искажает ни одного пикселя, значит на экране ровно те же пиксели, что уйдут
на термоголовку. Никакого второго рендера для «удобной ориентации» не нужно.

### Контекст

Схема «сервер рендерит, клиент показывает и посылает координаты обратно» —
это, по сути, тонкий клиент. Она уместна, когда рендер сложный и должен быть
единственным (печать, PDF, CAD-превью, научная визуализация), а интерактивность
сводится к манипуляции небольшим набором параметров. Не подходит, когда нужна
мгновенная реакция на каждый кадр (игры, рисование) или когда сервер далеко —
здесь он на `127.0.0.1`, и round-trip стоит единицы миллисекунд.

#### Блок 1. Утилиты (строки 12–38)

```javascript
const $ = (id) => document.getElementById(id);
```

Самодельный `$`. Не jQuery — просто короткое имя для `getElementById`.
Стрелочная функция с одним выражением: `(id) => выражение` — неявный `return`.
С фигурными скобками `return` пришлось бы писать явно:

```javascript
const $ = (id) => { return document.getElementById(id); };   // то же самое
```

```javascript
function debounce(fn, ms) {
  let t;
  return (...args) => { clearTimeout(t); t = setTimeout(() => fn(...args), ms); };
}
```

**Дебаунс** — «выполни функцию, только если её не вызывали снова в течение `ms`».
Каждый новый вызов отменяет предыдущий отложенный (`clearTimeout`) и ставит новый.

Как это работает: `t` живёт в **замыкании**. Возвращённая стрелочная функция
помнит `t` между вызовами, хотя `debounce` давно завершилась. Это классический
пример замыкания как контейнера состояния — в Python аналог делается через
`nonlocal` или атрибут функции.

`(...args)` — rest-параметр, собирает все аргументы в массив.
`fn(...args)` — spread, разворачивает массив обратно в аргументы.
Один и тот же синтаксис `...` в двух ролях, различаются по позиции:
слева от `=` (или в объявлении параметров) — сбор, в вызове — разворачивание.

В проекте четыре разных дебаунса с разными интервалами, и каждый подобран под задачу:

| Где | Интервал | Почему столько |
|---|---|---|
| `scheduleDragPreview` (268) | 110 мс | Перетаскивание: почти каждый кадр, но не чаще ~9 раз в секунду |
| `suggestPn` (256) | 200 мс | Автодополнение: успевает за быстрым набором |
| `scheduleBarcode` (148) | 250 мс | Валидация штрихкода — не срочно |
| `schedulePreview` (267) | 300 мс | Обычные правки полей |
| `doTranslate` (194) | 500 мс | Запрос в сеть + расход лимита API — дороже всех |

Логика подбора прозрачна: **чем дороже операция, тем больше задержка**.

```javascript
async function getJSON(url, opts) {
  const res = await fetch(url, opts);
  const data = await res.json().catch(() => ({}));
  if (!res.ok) throw new Error(data.error || `HTTP ${res.status}`);
  return data;
}
```

Обёртка над `fetch` из-за одной особенности: **`fetch` не бросает исключение
на HTTP 404 или 500**. Он reject-ится только при сетевой ошибке. Проверять
`res.ok` вручную на каждом вызове — гарантированно где-то забыть, поэтому
проверка централизована.

`res.json().catch(() => ({}))` — если тело не JSON (например, сервер вернул
трассировку), не падаем, а берём пустой объект. Скобки вокруг `{}` обязательны:
`() => {}` — это функция с **пустым телом**, а `() => ({})` — функция, возвращающая
пустой объект. Классическая ловушка стрелочных функций.

`data.error || \`HTTP ${res.status}\`` — сервер кладёт человекочитаемое сообщение
в поле `error` (`server.py:111`), и оно попадает прямо в UI. Если поля нет —
хотя бы код.

#### Блок 3. Защита от гонки ответов (строки 17–18, 270–292)

```javascript
let previewReqId = 0;

async function loadPreview(scale) {
  const myId = ++previewReqId;
  try {
    const data = await getJSON("/api/preview", {...});
    if (myId !== previewReqId) return;      // пришёл устаревший ответ
    $("exactImg").src = data.png;
    ...
```

**Проблема**: асинхронные ответы приходят не обязательно в порядке отправки.
Пользователь тянет блок, летят запросы A, B, C. Если A отработал медленнее C
(рендер зависит от содержимого), картинка от A перезапишет более свежую от C —
превью «прыгнет назад».

**Решение**: счётчик поколений. Каждый запрос запоминает свой номер в локальной
переменной `myId`. Когда ответ приходит, сравниваем: если глобальный счётчик
уже больше — значит, после нас был ещё запрос, и наш результат устарел.
Молча выходим.

`++previewReqId` — префиксный инкремент: увеличивает и возвращает **новое** значение.
`previewReqId++` вернул бы старое, и первый запрос получил бы `myId = 0`,
совпадающий с начальным состоянием счётчика.

Тот же приём для штрихкода (`barcodeReqId`, строки 152, 156).

**Альтернатива** — `AbortController`, который реально отменяет запрос:

```javascript
let previewAbort = null;
async function loadPreview(scale) {
  previewAbort?.abort();
  previewAbort = new AbortController();
  try {
    const data = await getJSON("/api/preview", { ...opts, signal: previewAbort.signal });
    ...
  } catch (e) {
    if (e.name === "AbortError") return;
    ...
  }
}
```

Строже (сервер перестаёт тратить силы на ненужный рендер), но требует
прокидывать `signal` и отдельно ловить `AbortError`. Счётчик проще и для
локального сервера достаточен.

```javascript
showPreviewError(/HTTP 404/.test(e.message)
  ? "Превью не отвечает: сервер запущен старой версией. Перезапустите "
    + "приложение (scripts/launch.sh restart)."
  : "Превью не построилось: " + e.message);
```

Специальная обработка 404 на `/api/preview`. Сценарий реальный: `launch.sh`
подтянул новую версию фронтенда из git, но старый серверный процесс ещё живёт
и не знает про новую ручку. Вместо загадочного «HTTP 404» пользователь получает
инструкцию. Комментарий рядом (строки 285–286) объясняет, почему ошибку нельзя
глушить: «тогда на месте превью остаётся пустая рамка и непонятно, что сломалось».

`/HTTP 404/.test(str)` — регулярное выражение как литерал (между слэшами),
метод `.test()` возвращает boolean. Тернарный оператор `cond ? a : b` — здесь
он растянут на три строки, что для длинных веток нормально.

#### Блок 4. Измерение миллиметра (строки 301–310)

```javascript
function measurePxPerMm() {
  const probe = document.createElement("div");
  probe.style.cssText = "position:absolute;visibility:hidden;width:100mm;height:0";
  document.body.appendChild(probe);
  const w = probe.getBoundingClientRect().width;
  probe.remove();
  if (w > 0) state.pxPerMm = w / 100;
}
```

Нужно перевести сдвиг мыши (в CSS-пикселях) в миллиметры макета. Формально
CSS определяет `1in = 96px`, значит `1mm = 96/25.4 ≈ 3.7795px`. Но браузерный
зум, `devicePixelRatio` и настройки масштабирования ОС могут это менять.

Решение: **спросить у браузера**. Создать невидимый элемент шириной ровно
`100mm`, замерить его фактическую ширину в пикселях, поделить.

Приёмы:
* `visibility: hidden` (а не `display: none`) — элемент не виден, **но занимает место
  и имеет размеры**. С `display: none` `getBoundingClientRect()` вернул бы нули.
* `position: absolute` — не влияет на поток документа, ничего не сдвинет.
* `height: 0` — не создаёт вертикальной прокрутки.
* Ширина `100mm`, а не `1mm` — деление на 100 в конце гасит ошибку округления
  субпиксельных значений.
* `if (w > 0)` — если что-то пошло не так (элемент не отрисован), оставляем
  теоретическое значение, а не ноль. Деление на ноль в `screenToDesign` дало бы
  `Infinity` и мгновенно сломало бы весь редактор.

Приём общего назначения: так же измеряют ширину скроллбара, поддержку CSS-свойств,
реальный размер шрифта.

#### Блок 5. Геометрия сцены (строки 312–343)

```javascript
function layoutStage() {
  const z = zoomFactor();
  const a = (state.angle * Math.PI) / 180;
  const w = 72 * state.pxPerMm * z;
  const h = 100 * state.pxPerMm * z;
  const bw = Math.abs(w * Math.cos(a)) + Math.abs(h * Math.sin(a));
  const bh = Math.abs(w * Math.sin(a)) + Math.abs(h * Math.cos(a));

  const vp = $("viewport");
  vp.style.width = `${bw}px`;
  vp.style.height = `${bh}px`;

  const wrap = $("labelWrap");
  wrap.style.left = `${(bw - 72 * state.pxPerMm) / 2}px`;
  wrap.style.top = `${(bh - 100 * state.pxPerMm) / 2}px`;
  wrap.style.transform = `rotate(${state.angle}deg) scale(${z})`;
}
```

**Габаритный прямоугольник повёрнутого прямоугольника.** CSS `transform: rotate()`
поворачивает элемент **визуально**, но в потоке документа он занимает своё
исходное место. Повёрнутая на 45° этикетка вылезет за границы контейнера
и обрежется.

Формула `bw = |w·cos α| + |h·sin α|` — стандартный axis-aligned bounding box
повёрнутого прямоугольника. Выводится проекцией сторон на горизонтальную ось.
`Math.abs` нужен потому, что косинус и синус отрицательны в части квадрантов,
а габарит всегда положителен.

`#viewport` растягивается под этот габарит, `#labelWrap` центрируется внутри —
поэтому этикетка не обрезается ни под каким углом.

`(state.angle * Math.PI) / 180` — градусы в радианы. `Math.cos`/`Math.sin`
в JavaScript, как и почти везде, принимают радианы. Одна из самых частых
ошибок в графическом коде — забыть конверсию.

`transform: rotate(...) scale(...)` — порядок трансформаций **имеет значение**:
они применяются справа налево, то есть сначала масштаб, потом поворот.
`scale(...) rotate(...)` дало бы другой результат при неравномерном масштабе
(здесь масштаб равномерный, так что разницы нет, но привычка думать о порядке полезна).

В CSS у `#labelWrap` задано `transform-origin: 50% 50%` (`style.css:128`) —
поворот вокруг центра, что и предполагает формула габарита.

#### Блок 6. Обратное преобразование координат (строки 384–391)

```javascript
// Экранный сдвиг мыши -> миллиметры макета: обратный поворот на тот же
// угол, на который повёрнуто превью, и деление на текущий зум.
function screenToDesign(sx, sy) {
  const a = (state.angle * Math.PI) / 180;
  const k = state.pxPerMm * zoomFactor();
  return [(sx * Math.cos(a) + sy * Math.sin(a)) / k,
          (-sx * Math.sin(a) + sy * Math.cos(a)) / k];
}
```

Самая концептуально плотная функция файла.

Пользователь двигает мышь вправо на 20 пикселей. Насколько и куда должен
сдвинуться блок **в системе координат макета**? Если превью повёрнуто на 90°,
то «вправо» на экране означает «вниз» в макете.

Матрица поворота на угол α:

```
[ cos α  -sin α ]
[ sin α   cos α ]
```

Нам нужно **обратное** преобразование (экран → макет), то есть поворот на `-α`.
Поскольку `cos(-α) = cos α`, а `sin(-α) = -sin α`, обратная матрица:

```
[  cos α   sin α ]
[ -sin α   cos α ]
```

Что и записано в коде. Для матрицы поворота обратная равна транспонированной —
свойство ортогональных матриц, и здесь оно видно невооружённым глазом.

Деление на `k = pxPerMm * zoom` переводит пиксели в миллиметры с учётом текущего
масштаба просмотра.

Возврат массива `[dx, dy]` и деструктуризация на месте вызова:

```javascript
const [ddx, ddy] = screenToDesign(e.clientX - startX, e.clientY - startY);
```

В JavaScript нет кортежей, массив из двух элементов — стандартная замена.
Деструктуризация `const [a, b] = arr` разбирает его по именам.

**То же преобразование ещё раз** — для стрелок на клавиатуре (строки 722–726):

```javascript
// стрелки двигают блок по экрану, а не по макету: если превью
// повёрнуто, «вправо» для глаза и «вправо» в макете — разные оси
const a = (state.angle * Math.PI) / 180;
nudge(m[0] * Math.cos(a) + m[1] * Math.sin(a),
      -m[0] * Math.sin(a) + m[1] * Math.cos(a));
```

Формула продублирована вместо вызова `screenToDesign` — потому что там ещё
делится на `k`, а стрелки задают шаг сразу в миллиметрах (0.5 или 0.1 с Shift).
Дублирование осознанное, но это кандидат на выделение общей функции
`rotateVec(x, y, angle)` — сейчас правка формулы требует помнить про два места.

#### Блок 7. Перетаскивание на Pointer Events (строки 393–429)

```javascript
function startDrag(ev) {
  if (!$("editMode").checked) return;
  ev.preventDefault();
  const el = ev.currentTarget;
  const key = el.dataset.key;
  select(key);

  const t = tweakOf(key);
  const startX = ev.clientX, startY = ev.clientY;
  const baseDx = t.dx, baseDy = t.dy;

  state.dragging = true;
  el.classList.add("drag");
  el.setPointerCapture(ev.pointerId);

  const move = (e) => {
    const [ddx, ddy] = screenToDesign(e.clientX - startX, e.clientY - startY);
    t.dx = baseDx + ddx;
    t.dy = baseDy + ddy;
    el.style.transform = `translate(${ddx}mm, ${ddy}mm)`;
    updateTweakRow(key);
    scheduleDragPreview();
  };
  const up = () => {
    el.removeEventListener("pointermove", move);
    ...
    state.dragging = false;
    saveTweaks();
    loadPreview();
  };
  el.addEventListener("pointermove", move);
  el.addEventListener("pointerup", up);
  el.addEventListener("pointercancel", up);
}
```

**Pointer Events вместо mouse/touch.** Один набор событий (`pointerdown`,
`pointermove`, `pointerup`, `pointercancel`) покрывает мышь, тачскрин и стилус.
До них приходилось писать два комплекта обработчиков и разбираться с эмуляцией
мышиных событий на тач-устройствах.

**`setPointerCapture(ev.pointerId)`** — ключевой вызов. Захватывает указатель:
все последующие события этого указателя идут **на этот элемент**, даже если
курсор ушёл за его границы. Без захвата быстрое движение мыши «теряло» бы блок,
как только курсор покидает маленькую рамку.

Раньше это решали подпиской на `document` и отпиской в `mouseup`. Захват
указателя делает то же самое, но чище: обработчики висят на элементе,
и `pointerup` гарантированно придёт туда же.

`pointercancel` обрабатывается **тем же** обработчиком, что `pointerup`.
Это событие приходит, когда система забрала указатель (жест браузера,
входящий звонок на телефоне, отключение стилуса). Без него драг завис бы
в состоянии `dragging = true` навсегда, и `applyBoxes` перестала бы обновлять рамки.

**`ev.preventDefault()`** — отменяет действие по умолчанию, здесь — выделение
текста при протягивании. В CSS дополнительно стоит `touch-action: none`
(`style.css:139`) — без него браузер на тачскрине перехватил бы жест как прокрутку.

**Замыкания вместо объекта состояния драга.** `startX`, `baseDx`, `key`, `el`
живут в области видимости `startDrag`; обработчики `move` и `up` их видят.
Не нужно ни класса `DragController`, ни полей в `state`. Каждый новый драг —
новый набор замыканий, изоляция автоматическая.

**`el.dataset.key`** — доступ к `data-*` атрибуту. `data-key="pn"` в HTML
читается как `el.dataset.key`. Стандартный способ привязать данные к DOM-узлу
без глобальных карт.

**Оптимистичное обновление**: рамка двигается **сразу** через
`el.style.transform = translate(...)`, а картинка приедет позже, когда сервер
ответит. Комментарий это фиксирует: «мгновенная реакция рамки, картинка догонит
следующим ответом сервера». Без этого при 110 мс дебаунса ощущалось бы залипание.

Обратите внимание: `translate(${ddx}mm, ${ddy}mm)` — CSS умеет миллиметры
в трансформациях, конвертировать в пиксели не нужно.

```javascript
function applyBoxes() {
  if (state.dragging) return;          // не ломаем перетаскивание на лету
  ...
}
```

Пересборка рамок во время драга уничтожила бы DOM-узел, на котором висит
захват указателя, и драг оборвался бы на середине. Один `return` на входе
решает проблему.

#### Блок 8. Изменение размера (строки 431–488)

```javascript
const grow = box.anchor === "center" ? 2 : 1;
const gw = box.gw || box.w, gh = box.gh || box.h;
...
if (axis.includes("e") && gw > 0) t.sx = clamp(baseSx + (ddx * grow) / gw);
if (axis.includes("s") && gh > 0) t.sy = clamp(baseSy + ddy / gh);
```

Две поправки, обе — про «чтобы ручка не отставала от курсора».

**`grow`**: блок с `anchor: "center"` (номер детали, штрихкод) растёт в обе
стороны от центра. Значит правый край смещается только на **половину** прироста
ширины. Чтобы ручка следовала за мышью один к одному, множитель масштаба
надо менять вдвое быстрее.

**`gw`/`gh`** — «на сколько миллиметров блок растёт при увеличении `sx`/`sy`
на единицу». Обычно это просто размер блока при масштабе 1, но не всегда:
у штрихкода **ряд выше самих полос** (`BARCODE_ROW["height_px"] = 73`,
а `bar_height_px = 58`), поэтому рамка и чувствительность ручки — разные величины.
Сервер считает это сам в `render._box()` (`render.py:196-209`) и присылает
в тех же данных, что и рамки.

Это тонкий момент проектирования: клиент **не пересчитывает** серверную геометрию,
а получает готовые коэффициенты. Формула в одном месте — в `render.py`.

```javascript
if (Math.abs(box.w - gw * baseSx) < 0.01) {
  el.style.width = `${w}mm`;
  if (box.anchor === "center") el.style.left = `${box.x - (w - box.w) / 2}mm`;
}
```

Проверка «а совпадает ли ширина рамки с шириной, вычисляемой из `gw`?».
Если да — рамку можно тянуть оптимистично. Если нет — это шапка, у которой
рамка всегда во всю рабочую ширину независимо от `sx` (`render.py:274`),
и трогать её нельзя.

Сравнение float через `Math.abs(...) < 0.01` — та же дисциплина, что в
`render.py:224`. Прямое `===` на вычисленных дробных значениях почти всегда даст `false`.

`ev.stopPropagation()` (строка 434) — предотвращает всплытие события к
родительской рамке. Ручка лежит **внутри** `div.hit`, у которого свой
`pointerdown` → `startDrag`. Без остановки всплытия потянув за ручку вы бы
одновременно двигали блок и меняли его размер.

#### Блок 9. `localStorage` и миграция схемы (строки 571–595)

```javascript
function loadTweaks() {
  const base = (state.layout && state.layout.tweaks) || {};
  const fresh = {};
  for (const key of Object.keys(base)) fresh[key] = { ...base[key] };
  let saved = {};
  try { saved = JSON.parse(localStorage.getItem(TWEAKS_KEY) || "{}"); }
  catch { saved = {}; }
  for (const key of Object.keys(fresh)) {
    const s = saved[key];
    if (!s) continue;
    // Правки, сохранённые до появления раздельных осей, читаем как sx = sy.
    const uniform = Number(s.scale) > 0 ? Number(s.scale) : 1;
    fresh[key] = {
      dx: Number(s.dx) || 0,
      dy: Number(s.dy) || 0,
      sx: Number(s.sx) > 0 ? Number(s.sx) : uniform,
      sy: Number(s.sy) > 0 ? Number(s.sy) : uniform,
    };
  }
  return fresh;
}
```

Четыре разных приёма в одной функции.

**1. Дефолт с сервера как база.** Начинаем не с пустого объекта, а с
`state.layout.tweaks` — это `layout.default_tweaks()`, приехавший в `/api/status`.
Значит, если в `layout.ELEMENTS` добавится седьмой блок, он появится
автоматически, даже если в `localStorage` его нет.

**2. Итерация по ключам дефолта, а не сохранённого.** Мусор из `localStorage`
(ключ, которого больше нет в макете) просто игнорируется — цикл идёт
`for (const key of Object.keys(fresh))`.

**3. Миграция схемы.** Раньше правка была `{dx, dy, scale}` — один общий масштаб.
Теперь `{dx, dy, sx, sy}` — раздельно по осям. Старая запись читается как
`sx = sy = scale`. Три строки, и пользователь не теряет настроенный макет
при обновлении. Та же миграция продублирована на сервере (`render._tweak`,
`render.py:192`) — потому что старый клиент может прислать старый формат.

Ключ `localStorage` при этом версионирован: `"cnh-label-tweaks-v1"`,
`"cnh-label-defaults-v2"`. Если формат изменится **несовместимо**, достаточно
поднять версию в имени ключа — старые данные просто не найдутся, а не сломают
приложение.

**4. Валидация каждого поля.** `Number(s.dx) || 0` — если в хранилище лежит
строка, `null` или `undefined`, `Number()` даст `NaN`, а `NaN || 0` даст `0`
(`NaN` ложен). `Number(s.sx) > 0` отсекает и `NaN`, и ноль, и отрицательные —
любое сравнение с `NaN` даёт `false`.

`{ ...base[key] }` — spread для **поверхностной копии** объекта. Без него
`fresh[key]` ссылался бы на тот же объект, что `state.layout.tweaks[key]`,
и правка пользователя мутировала бы «дефолт».

```javascript
try { saved = JSON.parse(...); } catch { saved = {}; }
```

`catch` **без параметра** — синтаксис ES2019. Раньше требовалось `catch (e)`,
даже если `e` не нужен. Данные из `localStorage` — недоверенный вход:
их мог испортить другой скрипт, старая версия приложения или сам пользователь
через DevTools. Разбор чужого JSON **всегда** в `try`.

Стоит помнить и про то, чего в этом коде нет: `localStorage.setItem` может
бросить `QuotaExceededError` (переполнение) или падать в приватном режиме
некоторых браузеров. `saveTweaks` (строка 593) не защищён — на настройках
в пару килобайт это не стреляет, но приём знать полезно.

#### Блок 10. Единая точка подписки (строки 671–737)

```javascript
function wireEvents() {
  $("find").addEventListener("click", findPart);
  $("pn").addEventListener("keydown", (e) => { if (e.key === "Enter") findPart(); });
  ...
  $("langRows").addEventListener("input", (e) => {
    if (e.target.dataset.lang) {
      $(`row-${e.target.dataset.lang}`).classList.add("edited");
      state.lines[e.target.dataset.lang] = e.target.value;
      updateLabelText();
    }
  });
```

Все подписки в одной функции — легко найти, что на что реагирует.
Альтернатива (`onclick` в HTML) размазала бы логику по двум файлам.

**Делегирование событий**: обработчик висит на контейнере `#langRows`,
а не на каждом из пяти полей. Работает благодаря всплытию (bubbling):
событие от вложенного элемента поднимается по дереву. `e.target` — где
событие возникло, `e.currentTarget` — на ком висит обработчик.

Зачем: поля создаются динамически в `buildLangRows` (строка 108). Без
делегирования пришлось бы вешать обработчик в момент создания и следить
за отпиской. Здесь контейнер один и живёт всегда.

`e.target.dataset.lang` служит и фильтром («это одно из наших полей?»),
и источником данных (какой язык).

**Класс `edited`** — метка «пользователь правил это поле руками».
Проверяется в `setLangValues` (строка 174): автоматический перевод
**не перезаписывает** отредактированные строки. Состояние хранится
не в `state`, а как CSS-класс на DOM-узле — приём спорный (состояние
в двух местах), но здесь оправдан: класс заодно управляет подсветкой,
и синхронизировать нечего.

```javascript
document.addEventListener("keydown", (e) => {
  if (!state.selected || !$("editMode").checked) return;
  if (/^(INPUT|SELECT|TEXTAREA)$/.test(document.activeElement.tagName)) return;
  const step = e.shiftKey ? 0.1 : 0.5;
  const moves = { ArrowLeft: [-step, 0], ArrowRight: [step, 0],
                  ArrowUp: [0, -step], ArrowDown: [0, step] };
  const m = moves[e.key];
  if (!m) return;
  e.preventDefault();
  ...
});
```

Стрелки двигают выбранный блок. Три защиты подряд:

1. Нет выделенного блока или выключен режим правки — выходим.
2. **Фокус в поле ввода** — выходим. Иначе стрелки в поле «Каталожный номер»
   двигали бы этикетку вместо курсора в тексте. `document.activeElement` —
   элемент с фокусом; проверка по `tagName` регуляркой покрывает три типа полей.
3. Нажата не стрелка — выходим (`moves[e.key]` даст `undefined`).

`e.preventDefault()` **только после** всех проверок — чтобы не ломать
прокрутку страницы стрелками, когда редактор неактивен.

`e.shiftKey ? 0.1 : 0.5` — точный шаг с Shift. Стандартная конвенция
графических редакторов.

**Объект как таблица переходов** (`moves`) вместо цепочки `if/else` —
компактно и расширяемо. Аналог `dict` в Python; в JS у объекта ключи всегда
строки, поэтому `moves[e.key]` работает напрямую.

#### Блок 11. Инициализация (строки 56–73, 743)

```javascript

```

**Один запрос — вся конфигурация.** `/api/status` возвращает геометрию макета,
список принтеров, дефолты, языки, состояние индекса. Не пять запросов, а один.

и границы ползунков.

**`{ ...status.defaults, ...loadDefaults() }`** — слияние объектов через spread.
Правый перекрывает левый, значит **сохранённые в браузере настройки побеждают
серверные дефолты**. Одна строка вместо `Object.assign({}, a, b)` или цикла.

**`init().catch(...)`** — `init` асинхронная, возвращает промис. Если он
отклонится (сервер не отвечает, битый JSON), без `.catch` получилось бы
необработанное отклонение промиса: ошибка только в консоли, страница молча пустая.
Здесь сообщение попадает в строку статуса, которую пользователь видит.

## Concepts Explained

### Design Patterns Used

| Паттерн | Где | Зачем |
|---|---|---|
| Debounce | `debounce()`, 4 применения с разными интервалами | Дорогая операция не запускается на каждое нажатие/движение |
| Request generation counter | `previewReqId`, `barcodeReqId` | Устаревший ответ не перезаписывает свежий |
| Optimistic UI | рамка двигается сразу, картинка догоняет | Интерфейс не залипает на время round-trip |
| Event delegation | обработчик на `#langRows` | Динамически созданные поля не требуют отдельных подписок |
| Pointer capture | `setPointerCapture` | Драг не теряется при выходе курсора за границы элемента |
| Single state object | `const state = {...}` | Всё изменяемое в одном месте, без фреймворка |
| Schema migration on read | `loadTweaks` (`scale` → `sx`/`sy`) | Обновление не ломает сохранённые настройки |
| Versioned storage key | `cnh-label-tweaks-v1` | Несовместимое изменение формата = смена имени ключа |
| Server-computed geometry | `box.gw`, `box.gh`, `box.anchor` | Формула живёт в одном месте — в `render.py` |
| Graceful init failure | `init().catch(...)` | Ошибка старта видна пользователю, а не только в консоли |

### Key Technical Concepts

#### Концепт 1: Замыкания как хранилище состояния

**Что**: функция, определённая внутри другой, сохраняет доступ к её переменным
даже после того, как внешняя завершилась.

**Почему здесь**: три применения подряд.
* `debounce` хранит идентификатор таймера в `t`.
* `startDrag` хранит начальную точку и базовое смещение в локальных переменных,
  которые видят `move` и `up`.
* `getJSON`-обёртки захватывают `myId` для проверки актуальности ответа.

Без замыканий каждое из этих состояний пришлось бы класть в `state` или
в глобальные переменные — и следить, чтобы два одновременных драга не переписали
данные друг друга.

**Когда применять**: приватное состояние без класса; фабрики функций;
обработчики событий, которым нужен контекст создания.

**Trade-offs**:
* Плюсы: изоляция без классов, естественно ложится на события.
* Минусы: **утечки памяти**, если замыкание висит в долгоживущем обработчике и держит большой объект (здесь `up` снимает все слушатели, поэтому утечки нет); отладка сложнее — переменные не видны в глобальной области.

**Ловушка, которую стоит знать** (в этом коде её нет, но она рядом):

```javascript
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 0);  // 3, 3, 3
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i), 0);  // 0, 1, 2
```

`var` создаёт **одну** переменную на всю функцию, `let` — новую на каждой
итерации. Весь этот файл использует `const`/`let`, ни одного `var` —
именно поэтому проблема не возникает.

**Что нужно знать**: область видимости (`var` vs `let`/`const`), lexical scoping,
цикл событий и очередь макрозадач.

#### Концепт 2: Асинхронность и гонки в UI

**Что**: `async`/`await` — синтаксис поверх промисов. `await` приостанавливает
функцию, не блокируя поток; браузер продолжает обрабатывать события.

**Почему здесь**: пять асинхронных операций (`/api/preview`, `/api/barcode`,
`/api/part`, `/api/suggest`, `/api/translate`), каждая может обогнать предыдущую.

**Когда применять счётчик поколений**: любой запрос, чей результат обновляет UI
и который может быть вызван повторно до завершения предыдущего — поиск,
автодополнение, превью, фильтры.

**Trade-offs**:
* Плюсы: две строки кода, работает всегда.
* Минусы: сервер всё равно посчитал ненужный результат; при частых запросах это лишняя нагрузка.

**Альтернативы**: `AbortController` (реальная отмена, сервер прекращает работу);
`switchMap` в RxJS (та же семантика, декларативно); очередь с ограничением
параллелизма.

**Что нужно знать**: цикл событий, микро- и макрозадачи, что `await` не блокирует
поток, что `fetch` не бросает на HTTP-ошибках.

#### Концепт 3: Преобразования координат

**Что**: одна и та же точка в разных системах отсчёта. Здесь их три:
экранные CSS-пиксели, миллиметры макета (портрет 72×100) и миллиметры печати
(ландшафт 100×72). Переход между ними — поворот и масштаб.

**Почему здесь**: превью повёрнуто на произвольный угол и отмасштабировано зумом.
Сдвиг мыши в экранных пикселях нужно превратить в сдвиг блока в миллиметрах макета.

**Когда применять**: любой редактор с зумом и поворотом — графические,
карты, CAD, схемы. Правило: **выберите одну «каноническую» систему координат
и храните всё в ней**, преобразуя только на границе с пользователем.
Здесь каноническая — миллиметры макета: и `tweaks`, и `boxes`, и всё,
что уходит на сервер.

**Trade-offs**:
* Плюсы: одна система для хранения — нет рассинхрона; данные не зависят от того, как пользователь смотрит.
* Минусы: преобразование легко забыть (стрелки на клавиатуре — отдельный случай, где его пришлось написать второй раз).

**Альтернативы**: `DOMMatrix` — браузерный API для матричных операций,
умеет `inverse()` и `transformPoint()`; для сложных сцен предпочтительнее
ручной тригонометрии. Библиотеки вроде `gl-matrix` — когда преобразований много.

**Что нужно знать**: матрица поворота; что для неё обратная = транспонированная;
радианы vs градусы; `transform-origin` в CSS и порядок применения трансформаций.

---

#### Концепт 4: Pointer Events

**Что**: единая модель событий указателя (мышь, тач, стилус), заменившая
раздельные `mouse*` и `touch*`.

**Почему здесь**: редактор макета должен работать и мышью, и пальцем на планшете.
С Pointer Events это один комплект обработчиков.

**Когда применять**: любое перетаскивание, рисование, жесты. Обязательный набор:
`pointerdown` → `setPointerCapture` → `pointermove` → `pointerup` **и**
`pointercancel`.

**Trade-offs**:
* Плюсы: один код на все устройства; захват решает проблему выхода за границы.
* Минусы: нужно помнить про `touch-action: none` в CSS (иначе браузер съест жест как прокрутку) и обязательно обрабатывать `pointercancel`.

**Альтернативы**: HTML5 Drag and Drop API (для перетаскивания **между**
контейнерами, неудобен для свободного позиционирования); библиотеки
(`interact.js`, `dnd-kit`) — если нужны инерция, привязка к сетке, мультитач.

**Что нужно знать**: всплытие и перехват событий; `target` vs `currentTarget`;
`preventDefault` vs `stopPropagation` (первое отменяет действие браузера,
второе — распространение события).

2. **Посмотрите на протокол**: откройте DevTools → Network, отфильтруйте по
   `preview` и потяните блок. Увидите пачку POST с интервалом ~110 мс и один
   финальный после отпускания — дебаунс и «финальная картинка в полном качестве»
   (`app.js:424`).

3. **Проверьте миграцию схемы**: положите в `localStorage` запись старого формата
   и перезагрузите страницу — блок должен ужаться по обеим осям.

   ```javascript
   // в консоли браузера
   localStorage.setItem("cnh-label-tweaks-v1", JSON.stringify({pn: {dx: 2, dy: 0, scale: 0.8}}));
   location.reload();
   ```

4. **Глубже**: вынесите поворот вектора в одну функцию и используйте её
   в обоих местах (`screenToDesign` и обработчик стрелок, строки 386 и 724) —
   сейчас формула продублирована. Затем добавьте undo: стек
   `{key, before, after}`, куда `up`-обработчик кладёт запись, и `Cmd+Z`,
   который её снимает.

5. **Осторожно с**:
   * `applyBoxes()` во время драга — снесёт DOM-узел с захватом указателя (защита есть, не убирайте);
   * `pointercancel` — если убрать этот обработчик, драг зависнет при системном прерывании жеста;
   * `touch-action: none` в CSS — без него редактор не работает пальцем;
   * изменением формата `tweaks` без поднятия версии в `TWEAKS_KEY` и без правки `render._tweak` — клиент и сервер разъедутся;
   * `state.pxPerMm` — если `measurePxPerMm` вернёт 0, весь редактор превратится в `Infinity`; проверка `if (w > 0)` там не косметическая.
